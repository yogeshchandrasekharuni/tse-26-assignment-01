# Report sources and evidence

The editable report is generated by `scripts/build_report.py` from the prose in `reports/content.json`, the frozen contracts, and measured campaign artifacts. Figures are authored vector geometry. Canonical statistics and Wilson intervals come from the evaluated evidence; drawing coordinates may use floating point.

`make report-draft` produces a visibly marked working PDF while the live campaign is incomplete. `make report` must reject incomplete headline evidence or missing full offline reproduction. The final document must contain 10-12 pages and every rendered page must be inspected. No author names have been supplied; none are inferred.

Provider usage is a separate report-side audit of the immutable raw response channels. It does not change the frozen evaluation implementation or its outcomes. Run `scripts/audit_provider_usage.py` on a completed live campaign. The audit includes physical failed attempts, deduplicates reused source executions by scanning physical directories once, preserves unavailable fields as null, and distinguishes recorded responses from provider-attempt telemetry. Cached prompt tokens are a subset of prompt tokens.

Primary references and the limited claims they support are recorded in `sources.json`. These references explain methods and framework behavior; they are not evidence that this application or any experiment ran. Empirical claims must link to repository artifacts.

`data/pilot-clean-checkout.json` records the latest successful rehearsal from initially clean revision f7c11d6: offline setup/data,72 Python tests plus frontend checks, framework playback and all nine pilot comparisons. Earlier aa2c022 success and the initial setup failure remain preserved under artifacts/verification: hard-coded cache paths originally prevented offline Python discovery. The Makefile now honors explicit cache/install-directory overrides. This pilot evidence cannot pass the final report's full900 scope check.

After the full live aggregate exists, run `scripts/prepare_diagnosis.py` with the repository Python. It indexes the top three naturally violated relations by the frozen ordering and the first failing base/seed, with a passing neighbor where available. Its output is explicitly `requires_review`; it never infers a cause. The verified final `data/diagnosis.json` must bind `campaign_id`, `headline_sha256`, a concise `summary`, evidence-based `report_blocks` and `supporting_artifact_hashes`. Zero or fewer than three nonzero relations must stay honest. The final report uses those reviewed blocks in place of its draft methodology placeholders.

The final submission checker verifies report input hashes, the full offline comparison, current provider audit against raw live responses, the diagnosis's supporting evidence, and the SHA-256 of the twelve visually inspected final PDF pages. Derived audits may change with a versioned reporting correction; immutable raw campaign attempts do not.
