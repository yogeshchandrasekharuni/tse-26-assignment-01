# Bounded replay interpreter lifetime

The per-leg full-GC policy in the first seed-attribution adapter was too costly over a long campaign. The auxiliary v1 clean playback was stopped after210/900 completed comparisons; every completed prefix case matches its live semantics, and all15,959 generated files are archived separately. A recorded sample still showed4,125,472KB RSS despite full collection after every leg. We do not infer a particular upstream library defect from that observation.

The isolated auxiliary benchmark repeats the same real four-decision failed playback sixteen times per condition. It makes no new model calls or empirical samples. With collection every leg, process CPU was3,9673437112.48 ns, including2,363913483.60 ns of explicit collection. With one collection after sixteen legs, process CPU was1,10408126538.53 ns, including185,6004651.49 ns of collection. Native max-RSS readings were313,425,920 and316,014,592; they are recorded without a portable unit assumption. These small controls do not establish full-workload peak memory or a general speedup.

Revision `bounded-process-playback-2` uses one ordinary local process at a time, replacing it after at most sixteen physical analyses. Each process calls the frozen CampaignRunner.leg and production run_analysis; it reconstructs the immutable source/follow-up from the frozen case and verifies the entire expected execution identity before playback. It returns the newly computed typed result over IPC. The parent retains only freshly recomputed successful-source outputs under the unchanged cache policy. No live final answer is loaded to execute an analysis. Historical failed-seed attribution retains revision1 and its uncorrected record/provenance.

These are harness processes for resource containment. Each analysis still has one public Fast Agent Orchestrator with its original internal agents, tools and captured decisions. No new distributed service or agent topology is introduced.

Checked the installed Python3.15 ProcessPoolExecutor signature and [official lifetime/spawn documentation](https://docs.python.org/3.15/library/concurrent.futures.html#concurrent.futures.ProcessPoolExecutor), including the3.15 worker-recycling deadlock fix. The main script is import-safe for spawn. An actual integration test recomputed one passing and one naturally failing pair, required exact frozen case semantics, and proved process replacement across the middle of a source/follow-up pair after three physical legs in that test. A changed parent identity is rejected before execution. The strengthened mid-pair rotation tests passed in7.61seconds. The complete benchmark outputs are preserved in auxiliary-resource-playbacks.tar.gz and its verified hash inventory.
