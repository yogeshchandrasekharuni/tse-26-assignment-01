# Evaluation implementation decisions, version 2

The original assignment governs coursework requirements. The handoff MR catalog 1.0 and base-level statistical semantics remain in force. These implementation decisions were made before headline evaluation.

- Case evidence uses the strict Pydantic `case-2` contract. It nests complete source/follow-up execution lineage rather than flattening it into the handoff's illustrative case JSON schema. It retains requested/effective seeds, exact identities, status, error subtype, numeric comparison count, differences, tolerances and paths.
- Headline evidence uses `headline-2`: rates and Wilson endpoints are **24-place decimal strings**. Computation uses Decimal at precision60, including its square root; no binary floating point enters filtering, canonical statistics, comparisons or confidence intervals. This deliberately supersedes the handoff headline JSON schema's `number` fields to honor the user's exact-arithmetic instruction. Counts remain JSON integers. Unobserved rates and intervals are null.
- Coverage revision2 intersects group g10's three candidate slices with inclusive raw sqft2100–2110. Other ZIP/type/bedroom/window definitions remain as supplied. Input-only preflight showed the preliminary1750–1760 band added no observations under MR05 widening, so it was rejected before any pilot/headline outcome. Its preliminary pilot cohort remains preserved as configs/pilot-cohort-v1.json and was never model-evaluated. The revised band gives MR05 added-row witnesses while retaining genuinely sparse months and odd/even cardinalities. Eligibility and all transformations are independently checked from raw CSV bytes; no model result controls eligibility.
- Transform seeds follow the exact SHA-256 recipe in the supplied seed manifest. The fixed paired model seeds are104729,130363,155921. The model profile revision is housing-qwen-v4, with65,536 context and1,024 completion reserve; all three full digests/defaults are frozen in configs/model_manifest_v4.json. Earlier profile manifests remain historical evidence.
- Production capture revision2 preserves native tool-call order separately from sorted JSON keys. Its semantic input also records message tool-call order. Timing/usage channels and root message timestamps are the only excluded audit fields. Every response and ordered call list is integrity checked. Detached child names can repeat across turns; each one-decision child clone receives only its exact response packet. The parent's multi-turn queue is separate.
- A provider rejection explicitly identifying malformed native model tool-call syntax is an output-contract violation. Other provider unavailability, unexpected framework/child execution failures and workflow timeouts are infrastructure errors. Context or decision-budget exhaustion is an observable contract failure. No such failure becomes a successful all-null result.
- A campaign can reuse a completed **source** execution only under identical full production identity; each logical case records its source reuse lineage. Every follow-up is fresh. Live resume may restore a previously completed source with integrity checks; offline replay rebuilds its own source cache from newly recomputed outputs, never live final-answer files.
- Pilot results and injected index-omission controls are separate from the headline denominator. Official rows need thirty distinct completed eligible bases, all three seed pairs and no unresolved infrastructure errors. Reproducing a preserved natural violation is successful reproduction; the exit check does not require zero violations.

These are implementation/precision choices, not empirical findings. See NOTEBOOK.md and immutable campaign manifests for what actually ran.
